# DSH Ocean Remote — форк

Самостоятельный форк [liguobao/ds-harness-remote](https://github.com/liguobao/ds-harness-remote): собственный relay-сервер и плагин для DeepSeek Harness. Не официальный продукт DeepSeek. Не npm-пакет upstream: то, что лежит в npm под этим именем, — исходный проект, а не эта сборка.

Текущее состояние, проверенное на реальных машинах, и открытые пробелы описаны в [аудите](docs/audit/README.md). Планы следующих этапов — в [спецификациях](docs/specs/README.md).

## Что это

- **Ocean** — минимальный self-hosted relay: один аккаунт из переменных окружения, список устройств, WebSocket-транспорт.
- **Плагин** — Host на рабочей машине и Client на другой, поверх native DeepSeek Harness. Истории и сессии остаются на Host.
- **Транспорт** — Relay с end-to-end шифрованием (Noise IK). Проверенный режим — `forceRelay`; P2P/TURN на собственном сервере пока не работают.
- **Доверие** — новые ключи требуют локального подтверждения полного SHA-256 на обеих сторонах.

## Что проверено, а что нет

| Проверено на двух машинах | Не проверялось или отсутствует |
| --- | --- |
| Собственный HTTPS через Tailscale, перезапуск контейнеров | Сессия с ответом модели, streaming, tools, файлы |
| Relay/Noise, reconnect, переживание перезапуска процессов | Отзыв чужого устройства, смена ключа, история сессий |
| Ручное подтверждение ключей на обеих сторонах | Вход Host из интерфейса, выбор роли, кнопка подключения |
| Открытие workspace; создание — через native API | Обновление, backup/restore, диагностика |
| Отказ в доступе до подтверждения | Терминал, Codex/ACP, QR-вход, P2P/TURN; preview — проверен только отказ |

Подробности и точные границы: [реестр проверок](docs/audit/00-runtime-evidence.ru.md) и [матрица](docs/audit/02-matrix.ru.md).

## Требования

- Linux на обеих машинах; проверено на bigpc и ноутбуке.
- DeepSeek Harness **0.2.0-rc.2** — единственная проверенная версия. Другие версии SDK не заявляются.
- Свободный домен или приватный Tailscale-узел для сервера.
- Модель LLM для настройки не требуется; доступ модели нужен только для работы в сессии.

## 1. Сервер

Выберите один вариант и следуйте инструкции целиком:

- [Приватно через Tailscale](docs/tailnet-ocean.ru.md) — отдельный узел и HTTPS без портов на хосте. **Рекомендуется.**
- [Публичный домен и Caddy](docs/self-host-ocean.ru.md).

Сервер требует `DSH_SERVER_ACCOUNT` и `DSH_SERVER_PASSWORD` (минимум 12 символов). `DSH_SERVER_PUBLIC_URL` задайте явно: по умолчанию подставляется `http://localhost:<port>`, что годится только для локальной проверки. Демонстрационного сервера нет: без своего сервера плагин не подключается никуда.

## 2. Плагин

Собранный плагин лежит в этом репозитории (`packages/plugin`), публикации в npm нет. Порядок установки в отдельный профиль, конфигурация и запуск — в [инструкции по установке](docs/fork-install.ru.md).

Кратко: новый профиль с bundle `@deepseek-ai/dsh-base` и `@deepseek-ai/dsh-web-app`, зависимость `file:` на каталог плагина, запись плагина с `serverUrl` своего сервера и ролью `host` или `client`. Рабочий профиль DSH и его ключи при этом не меняются.

## 3. Доверие между устройствами

Откройте «Ключи» в боковой панели на обеих машинах. Сначала Client подтверждает ключ Host, затем Host — ключ Client. Нужен **полный** SHA-256, сверенный по независимому каналу, а не скопированный из запроса.

Пошагово: [ручное доверие](docs/manual-peer-trust.ru.md).

## Ограничения этой сборки

- **Relay-only.** WebRTC/P2P/TURN на собственном сервере не работают: сервер не выдаёт TURN-креды.
- **Нет QR/OAuth-входа и регистрации по коду.** Соответствующих маршрутов на сервере нет; CLI-команды `login` и `register` для этого непригодны.
- **Нет входа Host из веб-интерфейса и выбора роли.** Пока настраивается через профиль.
- **Терминал, Codex/ACP и preview не входят в поддержку первого релиза.**
- **Нет снятия доверия и отзыва чужого устройства.**
- **Нет обновления, отката и backup.**
- **Мобильный, VS Code и браузерный клиенты (`apps/*`) не адаптированы.**
- Один writer на каталог идентичности; после неопределённой записи нужно офлайн-восстановление.

Веб-консоль сервера показывает устройства; пароль хранится в защищённом `.env` и не выводится.
