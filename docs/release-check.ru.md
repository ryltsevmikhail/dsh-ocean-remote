# Проверка чистой копии репозитория

Документ фиксирует, что проект **устанавливается, собирается, проходит тесты, проверку типов и контраст из свежего клона**, а не только в рабочем каталоге разработчика.

## Как воспроизвести

```
git clone file:///полный/путь/к/dsh-ocean-remote /tmp/dsh-clean-verify
cd /tmp/dsh-clean-verify
pnpm install --frozen-lockfile
pnpm --filter './packages/**' -r build
pnpm -r test
pnpm -r check
pnpm check:contrast
```

Требуется `pnpm` в `PATH`: скрипт `npm test` пакета `apps/android` вызывает `pnpm` напрямую.

## Ревизия и версии

| Параметр | Значение |
| --- | --- |
| Проверенная ревизия | `02f40c4` (origin/main на момент прогона) |
| Node.js | v26.12.0 (в CI используется 22) |
| pnpm | 9.15.4 (совпадает с CI) |

## Результат прогона

| Шаг | Результат |
| --- | --- |
| `pnpm install --frozen-lockfile` | Успешно, ~25 с, lockfile не менялся |
| `pnpm --filter './packages/**' -r build` | Успешно |
| `pnpm -r test` | **840 тестов** зелёные в 9 пакетах: crypto 7, protocol 78, browser 1, server 13, webrtc 44, client-core 41, vscode 7, android 149, plugin 500. Десятый участник `examples/mock-host` запускается с `--passWithNoTests` и тестов не содержит |
| `pnpm -r check` | Успешно (типы во всех пакетах) |
| `pnpm check:contrast` | 26 пар, обе темы |
| `pnpm check:limits` | 20 входов/мин, 240 API-запросов/мин, вход занимает слот, `GET /healthz` не ограничен |
| `pnpm check:mockups` | Требует Playwright и в чистом клоне не запускается: он падает с перечнем причин, а не пропускается молча |

Прогон не обращается к внешним API и сервисам. Зависимости ставятся из lockfile через npm registry (как в CI), поэтому для установки нужен доступ к registry или тёплый pnpm store; сборка, тесты, проверка типов и контраст работают локально.

## Повторная проверка рабочего checkout — 20 октября 2026

После изменений истечения запросов доверия, адаптива, подписей идентичностей и modal focus trap (`d066143`, `7d195f7`, `91227d8`, `bd91eaa`) выполнены сборка shared packages/plugin, `pnpm -r check`, полный `pnpm -r test`: **842 теста** в 9 пакетах (Plugin **502**, остальные количества как выше). `pnpm check:contrast`: **36 пар**. Production build Ocean, локальные `pnpm check:console`, `pnpm check:limits` и `pnpm check:mockups` (с явно заданным Playwright), проверка DSH bundle и `git diff --check` прошли.

Это **не новый прогон чистого клона**: таблица выше остаётся историческим доказательством для `02f40c4`. Здесь зависимости восстановлены через `pnpm install --frozen-lockfile`, lockfile не изменён. `pnpm` не был в PATH: команды запускались через `npm exec --yes --package=pnpm@9.15.4 -- …`; после восстановления workspace links разрешение локальных пакетов и общий check прошли. Внешних модельных вызовов не было.

Консольный smoke теперь сравнивает transition анимируемого поля входа (150 ms → 0.001 ms) и проходит четыре именованные клавиатурные остановки после завершённого refresh. Ширина 640 px **не** считается настоящим browser zoom 200 %. Для панелей отдельно выполнен [синтетический browser-render smoke](design/fork/05-panel-browser-check.ru.md), не native DSH E2E. Затем выполнен [native smoke панелей в новом профиле DSH](design/fork/06-native-panel-check.ru.md): результат ограничен показанными состояниями, не модельной сессией и не двухмашинным E2E.

## Зачем это нужно

- Ловит «работает только у меня»: отсутствующие workspace-связи, забытые файлы в `.gitignore`, скрытые зависимости от локальных артефактов.
- Даёт доказательство для приёмки: полный набор тестов проходит на том, что лежит в репозитории.

## Ограничения

- Android-тесты проверяют логику и рендереры, а не сборку APK и не устройство.
- `pnpm check:mockups` — локальная проверка дизайна: в чистом клоне без Playwright она намеренно падает.
- Реальных двухмашинных сценариев и вызовов модели здесь нет; они описаны в [приёмке сессии](session-acceptance.ru.md) и ждут отдельного согласования.
