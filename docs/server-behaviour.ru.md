# Что сервер Ocean знает и чего не умеет

Документ честно описывает ограничения, которые видны в эксплуатации. Часть из них — осознанные решения, часть — известные ограничения, которые нельзя «починить настройкой».

## Presence и `lastSeenAt` (A-30)

- Онлайн-статус устройства — **производная от открытого WebSocket**, а не от активности DSH. Устройство «онлайн», пока держится control-соединение; после закрытия оно становится офлайн.
- `lastSeenAt` обновляется **только при подключении WebSocket** (hello). Регистрация сохраняет прежнее значение, обновление токена его не трогает; у устройства, которое держит соединение, время «замирает» на моменте подключения.
- Отключение замечается по отсутствию pong: окно примерно 75 секунд, поэтому «только что офлайн» может выглядеть онлайн до этого окна.
- Практический вывод: «онлайн» — это «подключено к серверу», а не «пользователь сейчас работает». Для «работает ли сессия» смотрите состояние в самом DSH, а не в консоли.

## Веб-сессия живёт в памяти (A-31)

- Вход в консоль выдаёт cookie-сессию, которая хранится **в памяти процесса**: перезапуск сервера разлогинивает всех, повторный вход нужен заново.
- Ограничения: TTL 8 часов, не больше 256 сессий, cookie только для этого хоста, `SameSite=Strict`.
- Пароль аккаунта и токены устройств от перезапуска не страдают: устройства продолжают работать, переавторизация не нужна.

## Ограничение частоты за прокси (A-32)

- Лимиты считаются по IP сокета: API 240 запросов в минуту, вход 20 попыток в минуту. За обратным прокси это **IP прокси**, поэтому лимит общий для всех клиентов, а не по человеку.
- Вход тоже считается запросом API: успешный или неуспешный логин занимает один слот из 240. `/healthz` и `/ready` лимитом не ограничены — их можно опрашивать для мониторинга даже под нагрузкой.
- Счётчик входа считает **все** попытки за минуту, включая успешные, и накапливается на адресе прокси, а не на конкретном пользователе. Если сервер стоит за общим прокси, входы разных людей влияют друг на друга.
- Практический вывод: не ставьте этот сервер за прокси с общим адресом, если ожидается больше нескольких пользователей; прямого HTTPS (Tailscale) достаточно.

## Как это проверено

`pnpm check:limits` поднимает одноразовый сервер и проверяет границы на реальных запросах: первые 20 попыток входа проходят лимитер (и получают 401), 21-я — 429; после входа остаётся 239 из 240 запросов API, следующий — 429; `/healthz` отвечает 200 и в тот момент, когда API уже ограничен. За обратным прокси счётчики общие — это следствие того, что адрес один.

## Чего сервер не делает

- Не хранит историю сессий и не проксирует содержимое чата: через Relay идут зашифрованные кадры, сервер видит только метаданные соединения.
- Не отзывает чужие устройства по вашей просьбе, кроме действия владельца в консоли (`DELETE /api/v1/account/devices/:id`).
- Не обновляет и не бэкапит себя: это задачи эксплуатации ([operations](operations.ru.md)).
