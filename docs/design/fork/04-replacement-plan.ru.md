# План замены компонентов малыми проверяемыми частями

Статус: черновик. Каждый шаг — отдельный коммит с ревью, без изменения backend-контрактов (UX-12).

## Очерёдность

| Шаг | Объём | Проверка |
| --- | --- | --- |
| 1. Токены и типографика — **готово** | Семантические токены плагина (на `body`, где DSH объявляет свои алиасы) и состояния в Ocean; все компоненты переведены на них | контраст-скрипт (36 пар), сборка и тесты. Визуальная проверка заменена скриптом — живой рендер плагина не снимался |
| 2. Кнопки и поля — **готово** | Единый слой состояний, ограниченный контейнерами форка (не задевает остальной Harness UI): focus с клавиатуры, disabled, busy, aria-invalid, варианты primary (фон ink, как у Save) и danger | консоль проверена в браузере: Tab даёт outline 2px, поля входа — 44 px, hover не перебивает фокус; про плагин есть только сборка и тесты |
| 3. Уведомления и бейджи — **готово** | Общий слой: бейдж состояния Host, уведомление об обрыве (warning) отделено от ошибки старта (danger) — оба бара остаются карточками с цветной левой гранью, статус устройства в консоли оформлен тем же бейджем | консоль проверена в браузере (бейдж «Офлайн» — рамка 1 px, радиус 999 px); вид plugin-баров проверен только сборкой и тестами |
| 4. Карточка Remote — **готово** | Иерархия: статус → слои → список Host'ов → действия. Список Host'ов — группа с именем из существующего заголовка (`role=group` + `aria-labelledby`); прогресс уже был живым регионом (`role=status`, `progressbar` с процентом и подписью) | walkthrough требует второй машины — не выполнялся; критерий «ручной walkthrough» заменён на разметку и тесты, поэтому статус условный |
| 5. Панель доверия — **частично** | Полный SHA моноширинным стилем (токен исправлен: раньше он ссылался сам на себя), счётчик ожидающих запросов только при загруженном состоянии, «Сохранённых ключей нет» только когда роль доступна, разделение Host/Client, запрет подтверждения при смене ключа, метка legacy | смена ключа проверена кодом; тексты панели (счётчик, пустой список) вынесены в модель и покрыты 4 тестами; служба сохраняет до 32 уведомлений об истечении в пределах текущей роли/epoch, без ключей и права подтверждения; панель показывает «Запрос истёк» после обновления доверия. Атомарность pending/expired, cooldown, новая generation и очистка при закрытии покрыты core-тестами; изолированный Chromium render реального компонента с синтетическим control показал уведомление без действий подтверждения; это не проверка живого DSH lifecycle |
| 6. Карточка настроек — **частично** | Показано, что реально использует запущенный процесс: строка «Running now: …» появляется, когда сохранённые роль или адрес отличаются от работающих. Рантайм-конфиг отделён от сохранённого и меняется только при реальной замене, роль `both` считается Host — оба ложных баннера закрыты тестами. Остальное (источник значения, режим применения по полям, диагностика) — без изменений | покрыто 2 тестами (restart-ветка, роль `both`); сценарий в браузере не прогонялся |
| 7. Консоль Ocean — **готово** | Список устройств, карточка, отзыв, ошибки, доступные имена, подпись таблицы; на узком экране таблица складывается вместо растягивания страницы | проверено в браузере командой `pnpm check:console`: имена, подпись, фокус, 360 px и 640 px; настоящий browser zoom 200 % не проверен |
| 8. Адаптив и zoom — **частично** | Карточка Remote проверена в живом интерфейсе на 360 / 640 (узкий viewport, не настоящий browser zoom 200 %) / 768 / 1440: горизонтальной прокрутки нет, карточка влезает, целей меньше 32 px нет, ошибок страницы нет. Для консоли и переходов настроек добавлено уважение `prefers-reduced-motion`; консоль проверена на анимируемом поле входа (150 ms → 0.001 ms) | панели настроек и доверия дополнительно проверены в изолированном Chromium render с синтетическим control на всех четырёх ширинах и в двух темах: исправлены переполнение длинным сохранённым ID и потеря outline у SHA input, проверены 280 показанных controls и reduced motion ([границы и измерения](05-panel-browser-check.ru.md)). Это не оболочка DSH и не настоящий zoom; focus trap/return и screen reader ещё не приняты |

## Правила шага

- Не менять поведение и не ослаблять границы безопасности (approval только локально, полный SHA, CSRF, preview).
- Каждый шаг сохраняет рабочими сценарии 02–05; регрессии ловятся существующими тестами плюс браузерной проверкой.
- Сначала фиксируем состояние (скриншот + результат проверки), потом меняем; иначе «стало лучше» недоказуемо.

## Что показывается пользователю до масштабной переделки

1. Эта карта экранов, wireframes и UI kit (готовы).
2. **Макеты desktop и узкого экрана (не готовы)** — отдельный артефакт после согласования карты и kit: карточка Remote в состоянии «connected» и панель доверия с ожидающим запросом.
3. Список native-поверхностей, которые мы не трогаем (готов).

Согласование документов не утверждает макет: визуальное направление смотрится отдельно.

## Ограничения

- Не делаем второй экран сессии (чат, история) — только native.
- Не вводим мобильный клиент; адаптив касается панелей форка и консоли Ocean.
- Не заменяем security-модель ради меньшего числа подтверждений.
