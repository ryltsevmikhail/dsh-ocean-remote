## Осознанные отличия от текущего кода (целевое, не «как сейчас»)

- Подписи русские: сейчас часть строк английская (см. таблицу соответствия в [карте экранов](../01-screen-map.ru.md)).
- Клиентский собственный SHA показан отдельной строкой; в текущей панели его подпись сливается с ожидающим запросом.
- У кнопки «Подтвердить ключ» показано disabled-состояние, у уведомления об обрыве — номер попытки из бюджета 6.
- Подтверждение снятия доверия нарисовано отдельной строкой; в продукте сейчас `window.confirm`.

## Как проверяется

`pnpm check:mockups` рендерит каждый макет на 360/768/1440 и проверяет: нет горизонтального скролла страницы, поля SHA содержат ровно 64 символа и не обрезаны, у контролов есть доступные имена, у первой кнопки видимый фокус, есть заголовки разделов. Нужен Playwright, поэтому шаг помечен как **локальная проверка дизайна**: без него скрипт печатает `SKIPPED` и не делает вид, что проверка прошла.

## Что проверено по макету

- Полный SHA-256 переносится и **не обрезается** на 1440, 768 и 360.
- Опасное действие окрашено в danger, доступное имя содержит роль и ID; legacy не зелёный.
- Чекбокс независимой сверки **не предзаполнен**, кнопка подтверждения заблокирована.
- Слои «аккаунт / ключ / транспорт» показаны раздельно, обрыв не маскируется зелёным «Онлайн».
- Нет горизонтального скролла страницы на 360.

## Состояния, которые в макетах не нарисованы

Чтобы макет не смешивал противоречивые состояния, показано по одному состоянию на экран. Остальные описаны в [матрице состояний](../01-screen-map.ru.md):

- настройки: ошибка записи (текст `settingsOverridden` из локали, технические детали раскрываются отдельно), «загружаем», пустой профиль;
- консоль Ocean: пустой список, ошибка загрузки, частичный исход отзыва;
- ключи: истёкший запрос, столкновение ключа («Key: changed»), успешное подтверждение.

## Чего в макетах нет

- Светлая тема: показана только тёмная.
- Автоматическое измерение контраста не выполнялось (значения выбраны по целевым AA).
