# Чек-лист приёмки дизайна (UX-AC1…UX-AC5)

Статус: заполняется по мере работ. «Проверено» означает, что есть команда или артефакт, который можно повторить.

| Пункт | Что требуется | Как проверяется | Статус |
| --- | --- | --- | --- |
| UX-AC1 | Пользовательский путь 02–05 остаётся рабочим, security-тесты проходят на тех же контрактах | `pnpm -r test` из чистой копии репозитория ([проверка релиза](../../release-check.ru.md)): 834 теста, типы и контраст; чек-листы [установки](../../install-acceptance.ru.md) и [сессии](../../session-acceptance.ru.md) | Частично: полный набор зелёный в чистом клоне; живые двухмашинные прогоны ждут доступа к bigpc |
| UX-AC2 | Все состояния отображены и проверены: неверный пароль, истечение запроса, смена ключа, частичный отзыв, потеря сети | [макеты состояний](mockups/README.ru.md) для ошибки, пустого списка, истёкшего запроса и смены ключа; матрица [01-screen-map](01-screen-map.ru.md); живые прогоны | Частично: четыре состояния нарисованы и проходят автоматическую проверку; смена ключа проверена только кодом и тестами, живьём не прогонялась; неверный пароль — только в wireframes; частичный отзыв не прогонялся, а отдельного UI «запрос истёк» в продукте нет — истечение видно как исчезнувший запрос |
| UX-AC3 | Клавиатура и скринридер, нет фокуса за модалью и потери фокуса после закрытия | `pnpm check:mockups` (видимый фокус у всех контролов), ручной проход по диалогам | Частично: макеты проверены, живой интерфейс — нет |
| UX-AC4 | Визуальная проверка на согласованных viewport/темах/zoom; нет обрезанного SHA и скрытых последствий | `pnpm check:mockups` (360/768/1440 и 720/705 ≈ 200% зума по ширине, SHA 64 символа), `pnpm check:contrast` | Частично: макеты проверены; светлая тема и живой интерфейс — нет |
| UX-AC5 | Макеты и фактический UI показаны пользователю, ассеты/лицензии задокументированы | [макеты](mockups/README.ru.md), [UI kit](03-ui-kit.ru.md) | Ожидает показа: макеты готовы, визуальное направление не согласовано; лицензия base64-иконок вендоров остаётся открытым вопросом |

## Что автоматизировано

| Команда | Покрывает |
| --- | --- |
| `pnpm check:contrast` | 26 пар цветов консоли Ocean в двух темах, включая границы контролов и фокус |
| `pnpm check:mockups` | макеты на 360/768/1440/720/705 px: нет горизонтального скролла, SHA не обрезан, доступные имена, видимый фокус, цели ≥ 32×32 px, отсутствие CSS-анимации при `prefers-reduced-motion` |
| `pnpm -r test` | полный набор: 834 теста в 9 пакетах (плагин, сервер, протокол, crypto, webrtc, client-core, browser, vscode, android) из чистой копии ([проверка релиза](../../release-check.ru.md)) |

Ограничения автоматики: `check:mockups` эмулирует 200% зума только по ширине (высота окна 450 px) и видит лишь CSS-анимации, существующие на момент загрузки — переходы и анимации из JS не покрыты. Без Playwright шаг падает, а не пропускается молча.

## Что остаётся ручным

- Согласование визуального направления пользователем (UX-AC5).
- Живой проход по интерфейсу в обеих темах и на реальных диалогах (фокус-трап, возврат фокуса, скринридер).
- Двухмашинные сценарии (обрыв, отзыв, смена ключа) — ждут доступа к bigpc.
