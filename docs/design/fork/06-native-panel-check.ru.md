# Панели в настоящем DSH 0.2.0-rc.2 — 20 октября 2026

## Среда и изоляция

Проверка настоящего DSH Web и плагина, а не отдельного React renderer. Linux, Node.js v26.12.0, DSH `0.2.0-rc.2`; отдельные новые HOME/DSH_HOME/XDG_*/CODEX_HOME и рабочий каталог, loopback, новый Playwright browser context. Рабочий DSH, его профиль, ключи и браузер не использовались. Существующий CLI использовался только как исполняемый runtime по абсолютному пути.

Исходный прогон выполнялся до исправления focus trap, на сборке кода `91227d8` (последующие коммиты до `ad8c276` меняли только документы). Ниже SHA-256 артефактов на диске, зафиксированные до исправления; это не отдельная запись хеша каждого сетевого ответа браузеру:

- Host bundle: `ecf3936e9c17627b05b2848545ba4b4df0f9f4ac3fa8180b13826d8a3356a88b`.
- Client bundle, включая ordinary `client.js` и GitHub entry: `0a5506c29c486c2fd78130be6c0d2e6309792e52745a1bd7b7a5a02af10f9dbd`.

Сервер плагина задан как недоступный тестовый loopback `127.0.0.1:9`. Терминал и агентские бэкенды выключены. Вход в Ocean, модель и подключение второго устройства не выполнялись; credentials не вводились и не импортировались. Bootstrap URL обрабатывался только программно в памяти, не входит в отчёт. Onboarding пройден настоящими кнопками `Continue` и `Configure later`, без API key.

## Исходный native прогон (до исправления focus trap)

Открыты реальные footer-модалки настроек (`Remote settings`, отдельная от общих DSH Settings) и `Ключи` → `Доверие устройств`. Ширины 360 / 640 / 768 / 1440 CSS px, высота 1000 px; Light/Dark выбраны настоящими кнопками общих DSH Settings → General → Appearance, без CSS-инъекции или media emulation: **16 комбинаций**.

- Горизонтального переполнения документа и диалога нет, включая 360 px. Внутренние clientWidth/scrollWidth диалога: 318/318, 598/598, 726/726, 758/758.
- В каждой панели два собственных полных SHA-256 длиной 64 uppercase hex символа, отдельно Host и Client; на 360 px они переносятся строками. В светлом режиме дополнительно проверены DOM Range containment и отсутствие ellipsis.
- По 45 настоящих Tab/Shift+Tab в каждой комбинации. Dark 8/8 и Light trust 4/4 оставались внутри с outline; **Light config 4/4 после реального «Обновить доверие» дали BODY на первом Shift+Tab** (следующий Tab вернул Close). Это дефект, не keyboard acceptance; различие нельзя приписывать теме, поскольку перед dark-последовательностью Refresh не нажимался.
- Escape закрывает диалог и возвращает фокус на кнопку открытия: 16/16.
- Нижние элементы настроек доступны при прокрутке: сервер/роль, Host login, выключенный терминал, порты/Save access settings, Copy diagnostics. Без введённых учётных данных login ожидаемо disabled.

Причина воспроизведена отдельно в Chrome: элементы внутри закрытого `details` могут иметь непустой `getClientRects()`, но оставаться невидимыми и не фокусироваться. Старый trap принимал их за Tab-цели. Исправление добавляет настоящий `summary` и исключает скрытое содержимое закрытых disclosure, disabled и CSS-hidden элементы в обеих модалках. Повторная native проверка исправления описана ниже.

Это проверка показанного неавторизованного состояния. Pending/expired/trusted fixtures и длинные IDs проверены отдельно [синтетическим browser-render](05-panel-browser-check.ru.md), а не выданы за эти native данные.

## Повторный native прогон после исправления

Код `bd91eaa`; клиентские артефакты `client.js` и `client.github.js` на диске имеют SHA-256 `30c542d4b46687aa39fd4213f3f8985a78bcca287f5a472f13dd1c6e1da88166`. Новый независимый проверяющий использовал новые изолированные профили и browser contexts, тот же exact DSH и Google Chrome stable. Light/Dark переключались настоящими настройками DSH.

В каждой из **16 комбинаций** сначала нажата реальная «Обновить доверие» и дождались окончания обновления; затем по 45 Shift+Tab и 45 Tab — **1440 событий клавиатуры**. Дополнительно в настройках дождались появления agent details, раскрыли и снова свернули его.

Визуально отдельно просмотрены Light 360 px (низ настроек) и Dark 360 px (верх доверия); остальные размеры измерены DOM-проверками. Иногда native DSH показывал toast «Unable to create default workspace», перекрывающий верх: его не скрывали и не считают успешным workspace-сценарием. Ни Ocean, ни remote session/workspace lifecycle этой проверкой не принимались.

Собственные browser/process groups обоих native прогонов завершены; проверка `/proc` по их отдельным рабочим каталогам не нашла оставшихся собственных workspace-процессов. Это не заявление об остановке или проверке чужих процессов. Новые изолированные данные остались локальными тестовыми артефактами; в git их нет.

## Границы

- Ширина 640 px — viewport, **не** настоящий browser zoom 200 %.
- Screen-reader walkthrough не выполнялся.
- Реальные TTL expiry, legacy/changed-key/revoke и активная сессия не входят в этот прогон.
- Модельные сценарии и двухмашинные обрыв/отзыв по-прежнему требуют пользовательских gates.
