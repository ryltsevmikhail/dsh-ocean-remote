# Wireframes: setup → trust → connect → session, revoke и восстановление

Статус: черновик для согласования. ASCII-схемы показывают иерархию и состояния, не пиксели.

## 1. Setup (роль Client, не авторизован)

```
┌ Настройка Remote ───────────────────────────── ✕ ┐
│ Роль: [Client ▾]                                  │
│ Сервер: [https://<ваш сервер>            ]        │
│ Имя устройства: [laptop                     ]     │
│                                                   │
│ ┌ Вход ─────────────────────────────────────┐     │
│ │ Аккаунт  [                             ]  │     │
│ │ Пароль   [                             ]  │     │
│ │ [ Войти ]                                 │     │
│ └───────────────────────────────────────────┘     │
│ ⚠ Неверный аккаунт или пароль. Проверьте данные.  │
└───────────────────────────────────────────────────┘
```

Состояния: `loading` (плейсхолдер, не бесконечный спиннер), `empty`, `invalid` (ошибка под полем), `blocked` (кнопка недоступна без сервера).

## 2. Trust (первое подключение)

```
┌ Доверие устройствам ───────────────────────── ✕ ┐
│ Host на другой машине                             │
│  собственный SHA-256                              │
│  786A6E51...BC36BCAC   (64 символа, целиком)      │
│ Client на этой машине                             │
│  ожидающий Host                                   │
│  ID 01a154a4-…  generation …                      │
│  [x] сверил(а) по независимому каналу             │
│  [ Введите полный SHA-256                  ]      │
│  [ Подтвердить ключ ] [ Отклонить ]               │
│ Сохранённые ключи                                 │
│  ocean-stage5-host · Подтверждён вручную ·        │
│  [ Снять доверие ]                                │
└───────────────────────────────────────────────────┘
```

Состояния: `pending`, `expired` (запрос истёк — обновите), `changed key` (блок: «снимите доверие и подтвердите новый»), `legacy` (серый ярлык, не зелёный), `success`.

## 3. Connect

```
┌ Remote ─────────────────────────────────────── ✕ ┐
│ Account: signed in · Key: trusted · Relay         │
│ ocean-stage5-host · Online · Ready                 │
│ [ Повторить подключение ]                          │
└───────────────────────────────────────────────────┘
```

Состояния: `connecting` (этапы: проверка Host → авторизация пира → проба транспорта), `connected`, `failed` (причина + код + действие), `reconnecting` (номер попытки), `approval required`, `key changed`.

## 4. Session (native shell, наши элементы сверху)

```
[футер] Remote · Ключи · Настройка
┌ native: заголовок workspace · Host name · Exit ┐
│ native: список сессий / чат / композер          │
│ native: модель, режим доступа                    │
└─────────────────────────────────────────────────┘
```

Форк не рисует чат и историю; он отвечает за вход, доверие, подключение и выход.

## 5. Revoke / recovery

```
┌ Ocean: устройства ───────────────────────────────┐
│ ocean-stage5-client · Онлайн · Клиент            │
│ ... · [ Отозвать ]                               │
│  ┌ подтверждение ─────────────────────────────┐  │
│  │ Отозвать «ocean-stage5-client»?            │  │
│  │ Устройство потеряет доступ и должно будет   │  │
│  │ авторизоваться заново.                     │  │
│  │ [ Отозвать ] [ Отмена ]                    │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

Восстановление после смены ключа: «Key: changed» → «Ключи» → «Снять доверие» → Connect → новый полный SHA → подтверждение. Схема шагов повторяет [документ доверия](../../manual-peer-trust.ru.md).

## 6. Состояния, обязательные на каждом экране

`loading` · `empty` · `success` · `retryable error` · `blocked action` · `stale/expired` · `partial success` · `unsupported`.

Правила: ошибка — короткое объяснение + безопасный код + следующее действие; «неподдержано» показывается выключенным контролом с пояснением, а не молчанием; бесконечный спиннер запрещён.
