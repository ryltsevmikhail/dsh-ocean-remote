# Этапы Ocean: проверки и ревью

## Этап 1 — явный сервер (c683bd1)

Удалены fallback сервиса автора из плагина, TUI, CLI и install patch. Сохранённые адреса не стираются. Сборка и типы плагина, 396 тестов, проверка bundle и независимое read-only ревью прошли. Другие клиенты пока не адаптированы.

## Этап 2 — независимый серверный интерфейс

Удалены старые компоненты, тема, стили, три графических ресурса и зависимости Ant Design. Новый интерфейс написан для Ocean на React/CSS: вход, ручное обновление списка устройств, выход. По замечанию пользователя переработаны типографика, палитра, форма входа и мобильная компоновка; сохранены системная тема и отсутствие внешних графических/шрифтовых ресурсов.

Первое независимое ревью выявило: /app/remote не обслуживался при обновлении; login response сохранял лишний token в React state; после auth-перехода терялся фокус; китайская инструкция описывала удалённую страницу. Все замечания исправлены. В браузерной проверке обнаружен также отказ входной HTML-страницы при навигации с cross-site metadata: public static GET теперь разрешён, проверки Origin/Fetch-Metadata для всех API сохранены. В существующий auth-тест добавлен отказ cross-site GET к данным с Cookie.

Повторное независимое read-only ревью блокеров не выявило. Ограничение ревью: проверены текущие исходники, не полный git diff; ведущий отдельно сравнил lockfile: оставшиеся packages/snapshots не изменены, libc metadata сохранены, удалена только ненужная цепь Ant Design.

Проверки: серверные типы, production build и 12 core-тестов прошли на Node 26.12.0. Живой браузер на изолированном 127.0.0.1:18081 с одноразовыми тестовыми данными: вход, отображение пустого списка, повторное открытие /app/remote, выход, перевод фокуса и пустые localStorage/sessionStorage. Мобильная эмуляция 390px: ширина документа 390px, таблица скроллится в собственном контейнере. Осмотрены desktop/mobile screenshots. Это не проверка реального телефона, TLS или межмашинной сессии.

## Уточнение дизайна — палитра DeepSeek

По запросу владельца бирюзовая палитра заменена на синий акцент и нейтральные светлые/графитовые поверхности; знак и название Ocean сохранены. Первое независимое ревью нашло недостаточный контраст dark-hover кнопки и light muted-текста на wash. Исправлены отдельной переменной --button и затемнением muted; повторное ревью блокеров не выявило. Расчётный контраст primary 5.10:1, hover 4.86:1, light muted/wash 4.81:1. Типы и production build прошли на Node 22.23.3; тёмная тема осмотрена в браузере. Новый функционал и зависимости не добавлены, полный повтор core-тестов для изменения CSS не выполнялся.

## Этап 3 — локальная production-упаковка

На Node 22.23.3 прошли сборки protocol/server, проверка типов и 12 core-тестов. Прочитаны полные лицензии семи фактически разрешаемых пакетов; build создаёт проектную лицензию и полные third-party notices, включая публичную копию со ссылкой из консоли. При обновлении зависимостей генератор требует повторный аудит.

Проверка выявила, что pnpm 9 deploy включает 84 ненужных root-plugin-пакета даже с isolated linker. Вместо этого Dockerfile и локальная инструкция используют package-server.mjs: копируется только dist, protocol, ws и zod; каталог новый, symlinks внутри копируемого дерева запрещены. Правильный артефакт около 5.7 MiB по du; пробные неправильные артефакты удалены. Реально запущенный main из артефакта прошёл smoke: static HTML/assets/notices, HTTP Cookie auth, cross-site API denial, регистрация, отсутствие plaintext secrets в state, mode 0600, device credential после restart и сброс **активной** web-Cookie после restart. Не использовались профиль DSH, пользовательские пароли или существующая база.

Ревью упаковки и smoke выявило: проверялась уже разлогиненная Cookie, не все семь notices; отсутствовал signal cleanup; потеряны PNG/WebP MIME; затем обнаружены гонка сигнала во время stop и обход source-containment через symlink родителя output. Исправлено. Ведущий отдельно воспроизвёл отказ self-copy через alias, отказ EEXIST без изменения deployment, SIGTERM во время намеренно замедленного child stop: parent дожидается child, временные данные очищены. Финальное независимое read-only ревью двух скриптов блокеров не выявило. Эти проверки не доказывают HTTPS/браузерные Cookie-свойства или поведение контейнера.

## Этап 3 — Docker на bigpc

После выбора bigpc владельцем и его подтверждения Tailscale SSH: Docker 29.9.0, Compose 5.6.0 доступны без изменения групп/служб. Из git archive коммита e1cbedb в новом временном каталоге собран Dockerfile, build завершился успешно. База: node:22-bookworm-slim@sha256:c3de60bf2f9dd0ac6370e6117950ff62d6e339527e7472301c9c78a017978392. Проверочный образ dsh-ocean-remote:verify-e1cbedb, image ID sha256:58e1f1f904952959d96b75b4463460c150c11b44eb62e5f37adeda7a882500dc. Тег в Dockerfile пока плавающий; digest здесь фиксирует именно проверенную сборку, не гарантирует неизменность будущих сборок.

Отдельный сценарий на Python получил read-only safety review до запуска; работал с UUID-именами и метками, случайным test-only паролем в файле 0600. Контейнер: network none, без опубликованных портов и bind/socket mounts, только новый named volume /data, restart no, cap-drop ALL, no-new-privileges, init. Перед запуском проверены ownership/labels/mounts. Подтверждены Node22, USER node / UID1000, встроенный healthcheck, public HTML/notices и минимальный состав node_modules. HTTP Cookie auth, отказ неверного пароля/cross-site API, state без plaintext secrets и mode0600/UID1000 прошли. Device credential сохранился после docker restart и после удаления/создания нового контейнера с тем же volume; активная web-Cookie после restart недействительна.

После проверки отдельным чтением подтверждено отсутствие verification-контейнеров/volumes. Одноразовый env-каталог удалён helper; сборочный каталог удалён только после проверки его канонического точного пути. Образ сохранён для следующего тестового этапа. Работающий DSH, его данные и Tailscale Serve не менялись. Это не приёмка HTTPS, длительного WebSocket, Remote UI или настоящей сессии между ноутбуком и bigpc. Проверка LICENSE/NOTICE Node/OS base image не заявляется как выполненная.

## Следующий шаг — тестовый сервер через Tailscale

Владелец выбрал доступ только из tailnet. Основной HTTPS-порт bigpc уже обслуживает существующие службы; его маршруты не заменять. Для Ocean запланирован отдельный HTTPS-порт с loopback backend, отдельным состоянием и случайными тестовыми учётными данными. Развёртывание и межмашинная приёмка ещё не выполнены.
