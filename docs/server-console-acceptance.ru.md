# Приёмка веб-консоли Ocean

Проверка выполнялась на локальном сервере (`apps/server`, тестовые учётные данные, эфемерный `state.json`) в браузере. Внешние сервисы и рабочие данные не использовались.

## Что проверено

| Шаг | Результат |
| --- | --- |
| Неверный пароль | Появляется `role="alert"` с сообщением, пользователь остаётся на странице входа |
| Верный пароль | Открывается «Ваши устройства» |
| Пустой список | Показано «Пока ни одного устройства» с подсказкой, как подключить |
| Регистрация устройств через API | Два устройства появляются в таблице, подпись «0 из 2 устройств онлайн». Устройства **синтетические**: `deviceId` и ключ созданы запросом к REST API; вместо плагина DSH открывается настоящий WebSocket с кадром `hello`, как это делает плагин |
| Статус presence | До открытия сокета — ни одного онлайна; после `hello`/`hello.ack` устройство показано «Онлайн», подпись ровно «1 из 2 устройств онлайн» |
| Порядок строк | Онлайн-устройство зарегистрировано **вторым**, но показано первым — сортировка реально применяется |
| Отзыв владельцем | Кнопка «Отозвать» с подтверждением удаляет оба устройства; серверный список пуст |
| Выход | Возврат на страницу входа |
| Сессия после выхода | `GET /api/v1/auth/me` отвечает 401 |
| Ошибки страницы | 0 |
| Доступные имена | У всех кнопок есть имя; кнопка отзыва называет устройство |
| Подпись таблицы | Сообщает количество онлайн |
| Фокус | Первый Tab даёт видимую рамку |
| Узкий экран 360 px | Горизонтальной прокрутки страницы нет: таблица складывается внутри своей области |
| Ширина 640 px (≈200 % зума) | Горизонтальной прокрутки страницы нет |

## Как повторить

1. Собрать сервер: `pnpm --filter './apps/server' build`.
2. Запустить проверку: `pnpm check:console` (нужен Playwright; путь можно задать в `PLAYWRIGHT`).
3. Либо пройти шаги вручную: поднять сервер на loopback с тестовым аккаунтом и временным `state.json`, открыть `/app/login`.

Проверка автоматизирована: `pnpm check:console` поднимает одноразовый локальный сервер с тестовым аккаунтом и временным `state.json`, проходит вход (включая неверный пароль), пустой список, регистрацию двух устройств, открытие control-сокета для одного из них (`hello` → `hello.ack`), проверку статусов и сортировки, отзыв обоих устройств и выход, затем удаляет временные данные. Требуется Playwright (как и `check:mockups`); без него шаг падает, а не пропускается молча.

## Границы

- Прогон идёт на loopback: развёрнутый сервер по Tailscale и настоящий плагин DSH не участвовали. Присутствие проверено настоящим control-сокетом, но с синтетическим устройством.

- Проверен **локальный** сервер, а не развёрнутый на bigpc; сетевые задержки и Tailscale не участвовали.
- Не проверялись: ограничение частоты под нагрузкой, поведение при перезапуске сервера (сессии в памяти — см. [поведение сервера](server-behaviour.ru.md)), частичный исход отзыва при обрыве сети.
- Светлая и тёмная темы: контраст палитры проверяется скриптом `check:contrast`; визуальный проход по обеим темам в браузере не выполнялся.
