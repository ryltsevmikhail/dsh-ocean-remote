# Установка плагина форка

Статус: описывает **только этот форк**. Upstream-инструкции (`docs/installation.md`) относятся к чужому npm-пакету и hosted-серверу и здесь не применяются.

Проверено на Linux и DeepSeek Harness 0.2.0-rc.2 в отдельных профилях. Рабочий профиль DSH, его ключи и модели при этом не меняются.

## Что понадобится

- Клон этого репозитория и **собранный** плагин. В git лежат только два файла `dist` (`index.js` и `client.github.js`), а DSH читает клиентскую часть из `dist/client.js`, который в коммит не входит. Поэтому сборка обязательна.
- DSH 0.2.0-rc.2 и работающий сервер: [Tailscale](tailnet-ocean.ru.md) или [публичный домен](self-host-ocean.ru.md).
- Отдельный каталог для данных: свой `DSH_HOME` и пустой рабочий каталог. Не используйте текущий профиль.

## Шаги

### 1. Изолированные каталоги

Создайте новый каталог (например, `~/.local/share/dsh-ocean-test`) и внутри него пустые:

- `dsh` — будущий `DSH_HOME`;
- `workspace` — пустой рабочий каталог;
- `xdg/{config,cache,data,state,runtime}`, `os-home`, `codex-home`.

Все каталоги с правами `0700`. Это исключает чтение текущего профиля и его модельных ключей.

### 2. Профиль

В `dsh/profiles/<имя>/package.json`:

```json
{
  "name": "ocean-<имя>",
  "private": true,
  "dependencies": { "ds-harness-remote": "file:/абсолютный/путь/к/packages/plugin" },
  "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "ds-harness-remote"] } }
}
```

`@deepseek-ai/dsh-web-app` обязателен: без него не будет веб-интерфейса.

Плагин тоже должен быть **активирован**. Проще всего включить его в `dsh.profile.bundles` (как выше). Альтернатива — добавить запись плагина операцией `insert:` в конфигурацию профиля; одна лишь запись по `id` без bundle ничего не активирует (patch не находит запись). Одной зависимости в `dependencies` недостаточно: DSH установит пакет, но не активирует плагин — в интерфейсе не будет ни карточки настройки, ни кнопки «Ключи», а запросы к `/ds-harness-remote/*` вернут 404/405.

**Важно:** bundle-слой плагина включает не только активацию, но и собственный конфиг — `role: host` и `codex.enabled: true`. Поэтому шаг 3 обязателен: он полностью заменяет конфиг записи, включая выключение терминала, Codex и ACP.

Сначала соберите плагин в клоне: `cd packages/plugin && pnpm build`. Затем установите зависимости **внутри этого профиля** (`npm install --omit=dev --ignore-scripts --legacy-peer-deps` из каталога профиля). Ничего не устанавливайте глобально.

### 3. Конфигурация плагина

Bundle вставляет запись со своими значениями (в том числе `role: host` и включённый Codex). Задайте запись с тем же `id` в `cordis.patch.yml` профиля — она **заменяет конфиг целиком**, а не дополняет его, поэтому перечисленные ниже поля должны быть полными:

| Поле | Значение |
| --- | --- |
| `enabled` | `true` |
| `role` | `host` на рабочей машине, `client` на второй |
| `serverUrl` | адрес вашего сервера, например `https://<узел>.ts.net` |
| `deviceName` | понятное имя устройства |
| `forceRelay` | `true` — на своём сервере P2P/TURN не работают |
| `terminal.enabled` | `false` — не входит в поддержку релиза |
| `hostControl.enabled` | `true` на Host, `false` на чистом Client |
| `codex.enabled`, `cursor.enabled`, `acp.enabled` | `false` |
| `acp.backends[]` | все `enabled: false` |

Адрес сервера не имеет значения по умолчанию: без `serverUrl` плагин ничего не подключает.

### 4. Запуск

Запускайте DSH абсолютным путём к исполняемому файлу с чистым окружением (только `PATH`, `HOME` из нового каталога, `DSH_HOME`, `XDG_*`, `CODEX_HOME`), из пустого рабочего каталога:

```
<dsh> --profile <имя> --host 127.0.0.1 --port 0 --no-open
```

Строка готовности печатает локальный адрес с процессным launch-токеном: он действует, пока жив процесс, и по нему выдаётся cookie-сессия. Откройте её в браузере: получите cookie-сессию. Токен никому не передавайте и не сохраняйте в публичных файлах.

Не запускайте `--help` для профиля: он может подготовить и переписать профиль.

### 4a. Проверка установки

После входа по ссылке в боковой панели должны появиться «Ключи» и «Настройка Remote». В карточке «Настройка Remote» видны заданный сервер и выбранная роль; для роли Host там же есть форма входа, для Client — нет.

Если кнопок нет вовсе, плагин не активирован: проверьте `dsh.profile.bundles` (или явную запись плагина) и перезапустите DSH. Если кнопки есть, но карточка пишет «Remote plugin control is still starting», значит клиентская часть загружена, а серверная — нет: так бывает при явной записи без активации backend-части и во время старта.

### 5. Доверие

Новый Client увидит Host как неизвестный и не подключится, пока ключи не подтверждены на обеих сторонах: [ручное доверие](manual-peer-trust.ru.md).

## Ограничения

- Проверена одна версия DSH (0.2.0-rc.2); другие не заявляются.
- Вход Host и выбор роли доступны в карточке «Настройка» (кнопка в футере). Если значения заданы overlay-файлом профиля, запись из интерфейса отклоняется: правьте overlay.
- QR-вход и регистрация по коду не работают: серверных маршрутов нет.
- Один writer на каталог идентичности: не запускайте два процесса на одном `DSH_HOME`.
- Отсутствуют обновление, откат, backup и снятие доверия: см. [аудит](audit/02-matrix.ru.md).

## Удаление

Сначала отзовите устройство **с него самого** (единственный доступный маршрут — удаление собственной регистрации), затем остановите процесс и удалите созданный каталог. Рабочий профиль DSH не затрагивается. Чужое устройство сервер отозвать не может.
