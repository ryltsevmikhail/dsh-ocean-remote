# 03. Полноценная удалённая DSH-сессия

Статус: черновик. Зависимости: 01, 02; доверенная пара из 04 по действующему механизму. Итоговые revoke-негативы повторяются после завершения 04. [Общие правила](README.md).

## Цель и отличие от предыдущей проверки

Проверить не просто Noise/Relay и workspace metadata, а реальный lifecycle native DSH session: запрос модели, поток, разрешённый tool, отмена, история, повторное подключение и продолжение. Уже пройденный workspace/follow не считается доказательством этих операций.

## Условия model-теста — отдельный gate

- **SES-01. Разрешение.** До вызова фиксируются provider/model, способ авторизации без копирования рабочих ключей, лимит стоимости/токенов/длительности и разрешённые tools. Значения лимитов согласуются отдельно, не подразумеваются этим документом.
- **SES-02. Безопасный стенд.** Новый тестовый workspace с синтетическими файлами. Инструменты ограничены согласованной песочницей/процедурами native DSH; никаких команд в рабочем репозитории, внешних destructive действий, email/deploy/publish.
- **SES-03. Честные доказательства.** Детерминированный mock provider допустим для ошибок/порядка событий и автоматических регрессий, но не заменяет хотя бы один разрешённый реальный model turn. Без model-разрешения этап помечается частично, а не passed.

## Основной сценарий

1. Подключить подтверждённый Client к Host.
2. Создать тестовый workspace на Host, открыть его с Client, проверить canonical path/ID. Повторное открытие не создаёт дубль.
3. Создать native session и выбрать доступную модель. Видимые данные относятся к Host, не к локальному workspace Client.
4. Отправить один короткий запрос, получить streaming и завершённый ответ.
5. Попросить прочитать синтетический файл разрешённым tool; сравнить результат с содержимым на Host. Отдельно согласовать и проверить запись второго синтетического файла.
6. Запустить следующий достаточно длинный ответ, нажать Stop, увидеть подтверждённую остановку либо честное состояние «ожидаем остановки».
7. Открыть другую сессию, вернуться, выполнить reload Client и продолжить ту же исходную сессию.
8. Разорвать transport в отдельном тесте: сгенерированная на Host история не теряется; reconnect не отправляет prompt/tool второй раз автоматически.

## Функциональные требования

- **SES-04. Единственный источник истины.** Session/workspace IDs и persisted history принадлежат native Host. Client не подставляет локальную историю при disconnect и не создаёт её незаметно как fallback.
- **SES-05. Streaming.** Порядок и завершённость текста/tool events согласованы с Host. После reconnect есть reconciliation по native snapshot/cursor/другому поддержанному контракту, а не слепой append старых frames. Конкретный wire contract определяется аудитом SDK.
- **SES-06. Повтор отправки.** Идентификатор запроса/нативный механизм дедупликации предотвращает повторное выполнение при повторе transport delivery. Если API не даёт гарантии, UI показывает неопределённый исход и предлагает сначала сверить историю, а не делает автоматический resend.
- **SES-07. Cancel.** Stop относится к точной сессии/запуску. Отмена закрывает связанные subscriptions/owned resources, не останавливает чужой Client или другую сессию. После подтверждения cancel новые delta не добавляются к завершённому запуску; поздние события согласуются с финальным snapshot.
- **SES-08. Ошибки модели.** Отдельные безопасные состояния: отсутствует модель/credential, auth/лимит провайдера, timeout, tool failure, transport loss. Provider secrets и внутренние raw responses не выводятся.
- **SES-09. Files.** Путь и операции относятся к выбранному Host workspace; включённые read/write capabilities и native confirmations соблюдаются. Отказ в записи не представляется успешным save. При reconnect нет тихой перезаписи более новой версии.
- **SES-10. Несколько клиентов.** A и B не смешивают stream IDs, события и pending selections. Shared session mutation следует native concurrency contract: сериализация или явный конфликт, а не тихая потеря изменений. Закрытие A не уничтожает owned ресурсы B.
- **SES-11. Смена контекста.** При смене session/workspace/server/role отменяются старые UI subscriptions и выборы. Поздний ответ не появляется в новом контексте.
- **SES-12. Разрыв при генерации.** Client показывает, что исход неизвестен. Если Host продолжает запуск — это видно после сверки; если Host остановился — показывается итоговая ошибка. Reconnect не означает повтор prompt.
- **SES-13. Вложения и передача файлов.** Для включённых native upload/download операций проверить Client → Host передачу и обратное получение синтетического файла с совпадающими bytes/hash, объявленные size/type limits, cancel и ошибку частичной передачи. Нельзя выходить за разрешённый destination через имя/path traversal или показывать partial upload как готовое вложение. Обработка неподдержанного типа явная.
- **SES-14. Tool permissions.** Запросы native tool confirmation доступны и привязаны к точному session/run/action. Разрешение/отказ оператора исполняют Host policy, не обходят её и не подтверждают соседний action после reconnect. Stop не обещает отмену уже совершённого внешнего эффекта.
- **SES-15. Дополнительные native действия.** Аудит отдельно классифицирует retry/edit сообщений, archive/delete/search/history pagination/export, если они доступны в выбранном SDK. Действия, включённые в релиз, получают traceable сценарий; остальные скрыты или явно обозначены как неподдержанные, без фиктивных успешных кнопок.

## Тестовые случаи и приёмка

| ID | Проверка | Доказательство |
| --- | --- | --- |
| SES-AC1 | Create/open/session/history/reload | Реальные native IDs и совпадающая Host/Client история |
| SES-AC2 | Реальная модель + streaming | Разрешённый model turn, финальный ответ и учтённый бюджет |
| SES-AC3 | Tool read и согласованный write | Файл/хеш на Host, события tool и содержимое на Client |
| SES-AC4 | Cancel одной сессии при второй активной | Native состояние запуска, отсутствие остановки второй |
| SES-AC5 | Разрыв до/после send и во время stream | Нет автоматического повторного prompt/tool; reconciliation без дубликатов |
| SES-AC6 | Два Client и context switch | Нет пересечения событий/записей; конфликт обработки явно виден |
| SES-AC7 | Provider/tool/transport errors | Детерминированные негативные тесты и корректные UI states |
| SES-AC8 | Upload/download и tool confirmation | Совпадение bytes/hash, проверенные limits/cancel и решение точного action без auto-approval |
| SES-AC9 | Граница native полномочий | Trusted Client не обходит запрещённые routes/paths через encoding/canonicalization/symlink; разрешённые native owner-права описаны явно, без ложного обещания workspace sandbox |

Для каждого сценария фиксируется Host-side состояние, а не только текст Client UI. Нет лишних model turns: дорогостоящие edge cases преимущественно проверяются mock provider, реальный вызов ограничен согласованным бюджетом.

## Не входит

Новая собственная agent/runtime система, обучение/оценка качества модели, parity всех native tool integrations, автоматическое подключение рабочих provider accounts. Codex/ACP и терминал включаются только отдельным решением аудита и расширением приёмки.
