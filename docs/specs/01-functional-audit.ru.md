# 01. Функциональный аудит

Статус: черновик. Приоритет: P1, определяет остальные этапы. [Общие правила](README.md).

## Цель

Получить проверяемый ответ, что пользователь действительно может сделать текущим форком, что сломано, что отсутствует и что только предполагалось работающим. Аудит не является переписыванием проекта или формальным security audit всех зависимостей.

## Объекты

Ocean server UI/API и Docker; плагин Host/Client и CLI; поддерживаемый native SDK; конфигурация и credentials; роли, доверие, sessions/workspaces, файлы, транспорт; операционные инструкции. Старые приложения перечисляются как отдельные неподдержанные клиенты, а не смешиваются с native Web.

## Требования

- **AUD-01. Инвентаризация.** Зафиксировать компоненты, entrypoints, версии, артефакты и реально доступные пользовательские поверхности. Сопоставить source, shipped bundle и способы установки. Отличить upstream npm-пакет от нашего форка.
- **AUD-02. Матрица сценариев.** Для каждого сценария указать реализацию, ручные шаги, ограничения и доказательства. Статусы: `работает`, `частично`, `отсутствует`, `не проверено`. Неподтверждённое понижать до «не проверено», а не восстанавливать по старому рассказу.
- **AUD-03. Проверяемая среда.** Выбрать одну целевую версию SDK и описать совместимость API/слотов/settings/carrier. Проверить отдельно обычный plugin entry, выбранный bundle и CLI overlay, если они остаются поддержанными способами запуска.
- **AUD-04. Риски данных и полномочий.** Проследить, где находятся ключи/токены/история, какие методы создают owner peer, чем ограничены remote routes, preview и отзыв. Зафиксировать фактические native права на paths/tools/выполнение кода: не объявлять workspace sandbox там, где выдан полный owner доступ. Составить отдельные negative cases для реально запрещённых маршрутов и canonicalization/symlink обходов. Не включать реальные secret values в вывод.
- **AUD-05. Разделение контрактов.** Account authorization, криптографическое доверие ключу, установленный transport и доступность native API учитывать раздельно. «Online» не означает ни доверие, ни рабочую сессию.
- **AUD-06. Backlog.** Каждому пробелу присвоить ID, P0–P3, затронутые сценарии, воспроизведение, ожидаемое поведение, размер/зависимости и проверку исправления. Уже работающие части не переписывать без причины.
- **AUD-07. Решение о составе релиза.** Для terminal, preview, P2P/TURN, Codex/ACP и вспомогательной model generation явно выбрать: поддерживаем и принимаем; выключаем в первом релизе; отдельный последующий проект. Для каждой включённой optional capability нужен связанный тест-план happy path, permissions, failure/cancel и lifecycle. Для исключённой самостоятельной функции проверяются отсутствие активного UI и отказ её маршрутов; общие native owner-права описываются отдельно, не объявляются урезанными без доказательства. Не оставлять активную кнопку неподдержанной функции.
- **AUD-08. Различие документа и факта.** Проверить README/install/help/error hints на ссылки на чужой сервер, неверный npm package и обещания непроверенных возможностей.

## Обязательные строки матрицы

1. Установка/удаление/обновление форка в отдельном профиле.
2. Сервер не задан; неверный URL; недоступный сервер; TLS failure; несовместимый SDK.
3. Вход, неверный пароль, истечение auth, logout, смена сервера/роли.
4. Discovery, двухсторонний approval, reject/expiry, changed key, legacy provenance, revoke активного устройства.
5. Создать/открыть workspace; создать/продолжить сессию; история/переключение сессий.
6. Запрос модели, streaming, cancel, tools, файлы и ошибки провайдера.
7. Reload UI, restart Client/Host/Ocean, сетевой обрыв и повторное соединение.
8. Два Client, отсутствие пересечения streams/сессий и корректная изоляция lifecycle.
9. Backup/restore, rollback, stale lease/indeterminate state, диагностика без секретов.
10. Доступность функций из UI: не только наличие backend метода.
11. Trusted Client: запрет неподдержанных native/control маршрутов, approval/preview bypass, права на синтетические разрешённые и запрещённые paths с canonicalization/symlink cases согласно выбранному native контракту.

## Формат результата

Одна строка на пользовательский сценарий, например:

| ID | Пользовательское действие | Статус | Доказательство/версия | Пробел | Приоритет | Следующий этап |
| --- | --- | --- | --- | --- | --- | --- |
| пример, не результат | Новый Client продолжает сессию | не проверено | Нет реального model turn | Нужна приёмка | P1 | 03 |

Для блокирующего дефекта приложить минимальное воспроизведение. Ссылки на тесты должны позволять их найти и запустить; статический просмотр кода обозначается именно так.

## Приёмка

- **AUD-AC1:** все обязательные строки имеют статус и основание; нет «работает» только по mock/static evidence для заявленного E2E.
- **AUD-AC2:** пробелы спецификаций 02–05 связаны с backlog; нет потерянных P0/P1.
- **AUD-AC3:** выбранная платформа/SDK и scope релиза перечислены, недоступные поверхности обозначены.
- **AUD-AC4:** другой ревьюер может воспроизвести заявленный результат или зафиксированный отказ для чистой настройки, approval и native workspace. Обнаруженная недоступность получает статус/backlog и не блокирует завершение самого аудита. Model-сценарий остаётся «не проверено» до разрешённого прогона.
- **AUD-AC5:** отчёт не содержит credentials, auth URLs, приватных ключей и данных рабочего профиля.

## Выходные артефакты

Матрица аудита, backlog, карта компонентов/данных и решение о поддерживаемой версии. После их ревью уточняются оценки и спорные требования остальных спецификаций, без молчаливого расширения scope.
