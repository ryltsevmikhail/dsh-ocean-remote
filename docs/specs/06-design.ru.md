# 06. Дизайн и UX после функционального среза

Статус: черновик. Реализация после приёмки 02–05; подготовка карты состояний допустима раньше. [Общие правила](README.md).

## Цель

Привести Ocean и plugin controls к цельной, спокойной системе, а не раскрашивать текущий набор технических форм. Внешний вид upstream сохранять не требуется. Нельзя переписать native session UI только ради собственной оболочки и получить вторую несовместимую историю.

## Принципы

- Собственный интерфейс и лицензированные зависимости/иконки; не копировать непроверенный UI/ассеты.
- Визуальное направление — аккуратный DeepSeek-подобный синий акцент, сдержанная типографика и ясная иерархия, без заявления об официальной аффилиации.
- Один смысл — один термин. Host/Client/аккаунт/ключ/соединение/сессия не взаимозаменяемы.
- Никакого притворного success: security и operational states остаются видимыми, даже если портят красивый happy path.

## Информационная архитектура

**Ocean:** вход → устройства и их account/presence state → карточка конкретного ID → доступные owner действия → состояние сервера/безопасная диагностика.

**Плагин:** статус сервера/роли → выбор Host/соединение → native workspaces/sessions; отдельный доступный раздел ключей/запросов/отзыва и настройки. Ключевые действия доступны без поиска карточки в native Plugins page.

Account membership, local pin и transport state показываются раздельно. Local approval не переносится на серверную веб-панель ради красивого единого экрана.

## Требования

- **UX-01. Карта экранов.** До кода согласовать navigation/content map и wireframes: setup, список/карточка устройств, ключи/pending, connected/disconnected, настройки и диагностика. Отметить native и принадлежащие форку поверхности.
- **UX-02. Система компонентов.** Общие tokens цвета/spacing/type/radius/focus, кнопки/inputs/cards/dialogs/alerts/badges. Именованные semantic tokens success/warning/danger, не только набор hex.
- **UX-03. Полная state matrix.** Для каждого экрана: loading, empty, success, retryable error, blocked action, stale/expired, partial success и unsupported. Не использовать spinner бесконечно без причины/next action.
- **UX-04. Trust без двусмысленности.** Собственные Host и Client SHA подписаны по роли; полный fingerprint не обрезается и не заменяется коротким. Недоверенные имя/origin визуально отделены от факта проверки. Legacy не получает зелёный manual badge.
- **UX-05. Предотвращение ошибки.** Approve/revoke/rotate показывают точные role/ID/scope и последствия. Нет approve-all, скрытого автоподтверждения, опасного действия по default Enter или автоматически проставленного OOB checkbox.
- **UX-06. Настройки.** Видны effective value, источник override и режим применения. Секреты не появляются в summary/debug и не маскируются фиктивными сохранёнными значениями.
- **UX-07. Обратная связь.** Ошибка содержит короткое человеческое объяснение, безопасный code для поддержки и конкретное следующее действие. Технические детали раскрываются отдельно; их наличие не блокирует основной интерфейс.
- **UX-08. Accessibility.** Полная клавиатурная навигация, видимый focus, подписи форм и ошибок, focus trap/return в modal, Escape, screen-reader announcements для значимых async outcomes. Не полагаться только на цвет.
- **UX-09. Контраст/масштаб.** Цель WCAG 2.2 AA: обычный текст ≥4.5:1, крупный ≥3:1, controls/focus ≥3:1. При 200% zoom обязательные действия доступны; fingerprints/длинные IDs переносятся без потери символов.
- **UX-10. Responsive.** Проверить ширины 360, 768 и 1440 CSS px: без горизонтального скролла всей страницы, без недоступного submit/close, с читаемыми карточками/полным SHA. Адаптация Ocean/native plugin panel не означает реализацию отдельного mobile client.
- **UX-11. Темы и locale.** Поддержать темы, реально включённые аудитом, без нечитаемых наследованных цветов. Первичный язык новых пользовательских сценариев — русский; стратегия остальных locales явная, без смешения трёх языков в одной ошибке. Учитывать reduced motion.
- **UX-12. Функциональная неизменность.** Редизайн не ослабляет local-only approval, CSRF/auth/preview границы, полноту SHA и lifecycle states; backend/SDK контракты не меняются попутно без отдельной спецификации.

## Deliverables до реализации

1. Согласованная карта экранов и контента.
2. Wireframes основного setup → trust → connect → session и revoke/recovery paths.
3. Небольшой UI kit со state variants и источниками/лицензиями ассетов.
4. Макеты desktop/узкого экрана и список намеренно оставляемых native surfaces.
5. План замены компонентов небольшими проверяемыми частями.

Утверждение этих документов не утверждает конкретный макет заранее; визуальное направление проходит отдельный просмотр пользователем до масштабной переделки.

## Приёмка

- **UX-AC1:** пользовательский walkthrough 02–05 остаётся рабочим; security regression tests проходят на тех же backend контрактах.
- **UX-AC2:** все заявленные состояния отображены и проверены, включая wrong password, approval expiry, changed key, revoke partial outcome и network loss.
- **UX-AC3:** keyboard/screen-reader smoke и контраст проверены; нет фокусировки за modal и потери focus после закрытия.
- **UX-AC4:** визуальная проверка на согласованных viewport/темах/zoom; нет обрезанного SHA или скрытых опасных последствий.
- **UX-AC5:** макеты и фактический UI показаны пользователю; собственные ассеты/лицензии документированы.

## Не входит

Изобретение нового model chat вместо native DSH, коммерческий брендинг, дизайн отдельных мобильных/VS Code приложений и изменение готовой security модели ради уменьшения числа подтверждений.
