# Приёмка удалённой сессии (этап 03, часть 1)

Проверено на двух реальных машинах: Host на bigpc, Client на ноутбуке, каждый в отдельном изолированном профиле, собственный Ocean по приватному Tailscale HTTPS, `forceRelay`. **Модель не вызывалась** — согласование на реальный запрос ещё не получено, поэтому проверена только часть сценария, не требующая генерации.

## Что подтверждено

| Сценарий | Результат |
| --- | --- |
| Подключение из интерфейса | «Connected · Relay», слои «Account: signed in» и «Key: trusted» |
| Открытие удалённого workspace | Выбор строки и «Open workspace» перевели интерфейс в удалённый workspace |
| Заголовок и контекст | В шапке — имя Host `ocean-stage5-host` и «Exit»; в composer — модель `DeepSeek-V41-Flash`, режим `Workspace Write`, метка `Remote` |
| Добавление каталога как workspace | «Add remote workspace» → выбор существующего каталога → «Add and open»: интерфейс открыл удалённый workspace `os-home`, в реестре Host теперь два workspace |
| Создание сессии без запроса | Кнопка «New Session» убрала «No sessions yet»: сессия появилась, запрос не отправлялся, ошибок страницы 0 |
| Сессии сохраняются на Host | На Host появились каталоги `session-<uuid>` по одному на созданную сессию; файлы состояния ~340 байт, содержимого ответа модели нет |
| Перезагрузка страницы | После reload интерфейс остался в удалённом workspace, «No sessions yet» не вернулось (сессия присутствует в списке) |
| Ошибки браузера | 0 на всех шагах |

Удалённый workspace открывается в нативном интерфейсе DSH: composer, выбор модели и метка `Remote` относятся к Host. Содержимое списка сессий, история и переключение между сессиями не проверялись.

## Что не проверено и требует согласования

- Отправка запроса и ответ модели, streaming, стоимость.
- Остановка генерации.
- Чтение файла инструментом и подтверждение tool-действия.
- Запись файла.
- Продолжение той же сессии после перезагрузки с проверкой идентификатора и истории.
- Переключение между сессиями и содержимое их списка в интерфейсе.
- Создание нового каталога как workspace и произвольные пути.
- Ошибки провайдера (нет ключа, лимит, таймаут).

Реального вызова модели требуют: ответ, streaming, остановка генерации, инструменты и ошибки провайдера. Сверку идентификатора сессии и двух Client можно проверить и без генерации — это отдельная задача приёмки.

## Условия и границы

Изолированные профили созданы отдельно от рабочего DSH; его данные, ключи и модели не использовались. Тестовые процессы остановлены, launch-токены удалены. Провайдер модели в тестовых профилях не настраивался — интерфейс показывает модель Host, но запрос не отправлялся.
