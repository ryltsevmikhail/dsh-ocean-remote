# Приёмка чистой установки (этап 02)

Проверялось, что инструкция [«Установка плагина форка»](fork-install.ru.md) работает как написано — с нуля, без приватных тестовых скриптов и без текущего профиля DSH.

Условия: Linux, DSH 0.2.0-rc.2, обычный пользователь, новый каталог `~/.local/share/dsh-clean-check` (0700), пустой рабочий каталог, чистое окружение (`PATH`, новый `HOME`, `DSH_HOME`, `XDG_*`, `CODEX_HOME`). Сервер — собственный Ocean по приватному Tailscale HTTPS.

## Найденный дефект инструкции

Первая версия шага 2 указывала только `@deepseek-ai/dsh-base` и `@deepseek-ai/dsh-web-app`, а плагин — лишь как зависимость. В таком виде DSH ставит пакет, но **не активирует плагин**: запросы к `/ds-harness-remote/*` отвечают 405, а в интерфейсе нет ни «Ключей», ни «Настройки Remote» — клиентская часть плагина тоже не загружается. Сообщение «Remote plugin control is still starting» относится к другому состоянию: клиент загружен, а серверный маршрут недоступен.

Исправлено: `ds-harness-remote` добавлен в `dsh.profile.bundles`, в шаг 3 добавлено пояснение, что patch-запись с тем же `id` полностью замещает конфиг bundle-записи, а в шаг 4a — проверка установки и подсказка, что означает «control is still starting».

После правки весь путь прошёл повторно: плагин активировался, конфигурация применилась, интерфейс доступен.

## Границы проверки

Не выполнялись: вход по аккаунту с реальным паролем, подтверждение ключей между двумя новыми машинами, открытие сессии. Это уже проверялось ранее на других изолированных профилях ([приёмка доверия](manual-peer-trust-acceptance.ru.md)) и повторяется на этапе 03. Установка проверялась для роли Client. Для Host проверено только, что форма входа рендерится на отдельном профиле (см. [приёмку ручного доверия](manual-peer-trust-acceptance.ru.md)), но не успешный вход с реальными данными.

Тестовый каталог после проверки удалён, процесс остановлен, рабочий профиль DSH не затрагивался.
