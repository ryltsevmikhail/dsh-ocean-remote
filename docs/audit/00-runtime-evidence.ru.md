# Реестр фактических проверок до аудита

Что в этом проекте **уже проверялось на реальном оборудовании**, кем и с какими границами. Нужен, чтобы аудит не выдавал старые результаты за новые и не завышал статусы по памяти.

Все прогоны с двумя машинами выполнялись обычным пользователем, в отдельных HOME/DSH_HOME/XDG/CODEX_HOME, на паре bigpc (Host) + ноутбук (Client), с собственным Ocean по приватному Tailscale HTTPS (native DSH 0.2.0-rc.2). Рабочий профиль DSH, его ключи и модели не затрагивались. Детали: [приёмка транспорта](../dsh-ocean-acceptance.ru.md), [приёмка доверия](../manual-peer-trust-acceptance.ru.md).

Отдельно есть прогоны на одной машине (loopback): проверка чистой установки, консоли Ocean и входа плагина против локального сервера — см. [приёмку установки](../install-acceptance.ru.md), [приёмку консоли](../server-console-acceptance.ru.md) и [приёмку на одной машине](../local-pair-acceptance.ru.md). Такие результаты не считаются доказательством для сценариев с двумя устройствами.

## Обновление доступности bigpc — 20 октября 2026

После сообщения пользователя о восстановлении доступа выполнены только недеструктивные сетевые проверки с ноутбука:

- DNS bigpc разрешается в tailnet-адрес; `tailscale ping` получает pong, TCP/22 доступен.
- SSH доходит до remote protocol и завершённого key exchange; подтверждение host key не является причиной отказа.
- Далее SSH-аутентификация не завершается: authenticated=false, command_sent=false, конечный timeout. Санитизированная диагностика отмечает check/auth hint; конкретный способ подтверждения этим тестом не принимается. Прямое соединение без ProxyCommand также не дошло до выполнения команды.

Это **не** подтверждение доступной удалённой shell-сессии или приёмка двухмашинного сценария. Для продолжения нужно восстановить именно SSH-аутентификацию (включая операторский check, если он предлагается), а не менять VPN-настройки агентом. Auth-URL, ключи и raw SSH diagnostics в отчёт не включены; рабочие профили и сетевые настройки этой проверкой не изменялись. Собственные зависшие SSH-процессы остановлены. Модель не вызывалась.

## Подтверждено на реальных машинах

| Что | Результат | Границы |
| --- | --- | --- |
| Собственный Ocean: HTTPS через Tailscale, Docker, отсутствие host-портов | Работает | Один стенд, 2 машины |
| Восстановление после перезапуска контейнеров и пересоздания пары | Работает, IP/volumes/nodeID сохранены | Без reboot самого host/Docker daemon |
| Client подключается к Host через Relay/Noise | Работает, `transport=Relay`, native gateway | forceRelay=true; P2P/TURN не проверялись |
| Native workspace: создание и получение через follow-stream | Работает, совпадают ID и path | Только подготовленный тестовый каталог |
| Ручное подтверждение ключа на обеих сторонах через UI | Работает | Полный SHA-256, отдельный Chrome-контекст |
| Отказ в доступе до подтверждения (Host и Client) | Работает | Неизвестный peer отклоняется до Noise |

## Не проверялось ни разу

- Реальный ответ модели, streaming, остановка генерации.
- Инструменты (tools) и их подтверждения.
- Загрузка/скачивание файлов между Client и Host.
- Полный UI-сценарий: workspace → сессия → история → продолжение после reload. Частично закрыто позже: открытие удалённого workspace, создание сессии и её сохранение после reload — см. [приёмку сессии](../session-acceptance.ru.md); история, сверка ID и продолжение сессии не проверялись.
- Два Client одновременно в реальном сценарии.
- Отзыв работающего устройства, смена/потеря ключа.
- Обновление версии, rollback, backup/restore. Backup/restore позже проверен на изолированном профиле (см. [эксплуатацию](../operations.ru.md)); обновление и откат — нет.
- Обрывы сети и длительная работа.
- Codex/ACP, терминал; preview проверен только как отказ (см. выше), рабочего сценария не было.
- Настройка через интерфейс: `settings.server.set`, смена сервера и роли на живом приложении.
- Истечение и отклонение запроса доверия в реальном интерфейсе.
- История и переключение сессий, tools, ошибки провайдера.
- Stale lease и indeterminate-маркер на реальной ФС.
- Границы полномочий доверенного Client (запрещённые маршруты, обходы путей).
- Веб-консоль Ocean в браузере (список устройств проверялся через API плагина, не в консоли).
- Мобильный, VS Code и браузерный клиенты из `apps/`.

## Что это означает для статусов аудита

Всё из второй таблицы получает статус **«не проверено»**, даже если код выглядит готовым: наличие обработчика или unit-теста не доказывает рабочий пользовательский сценарий.

Обратное неверно: сценарий может быть частично подтверждён, если проверена только его часть. Такой сценарий получает **«частично»** с явно указанной проверенной границей — например, preview: отказ проверен, рабочее открытие нет.

«Работает» ставится только при наличии реального прогона **в описанных границах** и только на этом стенде (Linux, DSH 0.2.0-rc.2, две машины, свой Ocean).
