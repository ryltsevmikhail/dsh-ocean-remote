## Главные выводы

1. **Фундамент проверен, продукт — нет.** Транспорт Relay/Noise, ручное доверие ключей и открытие workspace подтверждены на двух реальных машинах. Сессия с ответом модели, файлы, отзыв устройства и эксплуатационные процедуры не проверялись.
2. **Установка ведёт не туда.** Инструкции предлагают upstream-пакет из npm и чужой сервер `dsh.r2049.cn`, хотя форк по умолчанию сервер не задаёт.
3. **Настройка неполная.** Вход Host и выбор роли есть в коде, но недоступны из интерфейса: диалог не зарегистрирован, RPC не вызывается.
4. **Отзыв доступа есть только для себя.** Владелец не может отозвать чужое устройство, поэтому этап 04 требует доработки сервера, а не только UI.
5. **Часть объявленных функций не работает на своём сервере:** QR/OAuth, регистрация по коду, TURN/P2P; терминал и агентские бэкенды включены по умолчанию, но не проверялись.
6. **Документация местами противоречит коду:** сервер по умолчанию, глобальные P2P/TURN-узлы, примеры версий, совет по `compose.yaml` за прокси.

## Что это не доказывает

Аудит не является security-аудитом зависимостей, образов и ОС. Статус «не проверено» означает отсутствие реального прогона, а не отсутствие реализации; статус «работает» ограничен условиями из [реестра](00-runtime-evidence.ru.md).
